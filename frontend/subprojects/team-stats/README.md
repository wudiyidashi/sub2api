# 团队消耗看板子项目

由 `D:\SelfDeveloped\28.sub2api_statistics_page` 的 Vue 看板迁入；原目录保持原样。这里维护总览、分组、排行榜、趣味统计、明细和设置六个页面。独立构建与样式环境，通过主后台的 `/admin/team-stats` 入口同源嵌入。

## 开发和发布

在 `frontend` 目录运行 `pnpm install --frozen-lockfile`，再运行 `pnpm dev`。主开发服务器同时提供子项目，不需要启动旧 BFF。依赖统一由 `frontend/package.json` 和锁文件管理。

- `pnpm build`：依次构建主后台和看板，产物一起嵌入 Go 程序，也进入现有 Docker 镜像和安装包。
- `pnpm build:team-stats`：单独构建看板至 `backend/internal/web/dist/team-stats`，不会清空主后台产物。
- `pnpm typecheck:team-stats`、`pnpm test:team-stats`：子项目校验。主 CI 同时检查两者。

## 认证与配置

主页面负责管理员路由保护、认证、令牌刷新和 API 调用。子页面仅通过同源父页面提供的统计请求接口访问允许的管理 API；直接打开子页面会提示从主后台入口进入。后端接口独立执行管理员认证和现有管理审计策略。

共享配置通过 `/api/v1/admin/team-stats/config` 存入现有 PostgreSQL 设置表。没有新增数据库、BFF 服务或服务器端管理员密钥。配置保存错误明确展示；读取失败时不允许用空配置覆盖已有分组。多名管理员编辑采用最后保存的配置，跨浏览器重新进入看板可读取最新配置。

旧看板迁移：先在旧页面导出配置 JSON，再到新看板的“设置”页导入。导入只保留展示偏好和分组，不迁入 `adminKey` 或 `baseURL`。不会自动复制旧 SQLite 数据，也不会删除旧服务或数据。每个密钥只能归属一个虚拟分组，避免重复计数；支持最多 100 个分组、合计 1000 个密钥。

## 数据口径

数据来自现有用量日志与聚合接口，不依赖完整请求／响应内容审计。费用显示 USD；旧页面的 CNY 选项只改符号而未换算，已移除。趣味消费类比中的汇率为固定示例，页面注明仅供参考。

日期按所选时区统计，结束日期包含当天。API 接受整日区间，因此原先的“近 24h”入口调整为“近 2 日”。自动刷新最少 30 秒，也可关闭。

地图、趣味统计和虚拟分组明细保留原页面的样本统计方式；全站总用量来自聚合接口。IP 地图使用最近最多 500 条明细，公网 IP 归属地通过 GeoJS 查询，私网 IP 本地识别。虚拟分组明细最多 20 个密钥，每个密钥读取最多 200 条；成本／耗时筛选在当前返回页或样本内进行。请以主后台“使用记录”查看完整分页明细。

仅开发构建允许 `?mock=1` 展示样例；正式构建禁用 mock 开关。
